# K230 相机标定拍照指南

## 一、能不能用视频代替拍照？

**可以，但不推荐。**

| 方式 | 优点 | 缺点 |
|------|------|------|
| **拍照** | 每帧都是精心摆位的，视角差异大，标定精度高 | 需要手动按保存 |
| **视频** | 自动录制，省事 | 连续帧视角变化极小，导致标定矩阵病态，误差大 |

> 如果坚持用视频，务必**间隔抽帧**（比如每 0.5~1 秒抽 1 帧），且保证棋盘格在画面中**大幅度移动**过。

**结论**：第一次标定建议老老实实拍照，15~30 张足够。后续熟悉流程了再考虑自动化。

---

## 二、拍照的核心原则

标定算法本质是解一个优化问题，需要棋盘格在画面中呈现**足够的几何多样性**。记住一句话：

> **"让棋盘格走遍画面的每个角落，摆出各种姿势。"**

具体是四个维度：

### 1. 位置覆盖（必须）
棋盘格中心要出现在画面的：
- 正中央
- 左上角、右上角、左下角、右下角
- 四条边的中间位置

目的：让标定算法知道画面边缘的畸变情况。

### 2. 距离变化（必须）
- **近景**：棋盘格占据画面 50%~70%（让角点很大，提取精确）
- **中景**：棋盘格占据画面 30%~50%
- **远景**：棋盘格占据画面 15%~25%（但角点必须仍能清晰识别）

目的：估计准确的焦距。

### 3. 角度倾斜（必须）
棋盘格平面相对相机光轴的倾斜角度：
- **正面**：棋盘格正对相机（0°）
- **轻度倾斜**：约 15°~30°
- **中度倾斜**：约 30°~45°
- **大角度倾斜**：约 45°~60°（极限，再大可能检测不到角点）

> ⚠️ **不要只拍正面！** 纯正面照片标定出来的焦距不准，径向畸变也估不准。

### 4. 旋转变化（建议）
围绕相机光轴旋转棋盘格：
- 正常横放
- 顺时针转约 15°、30°、45°
- 逆时针转约 15°、30°、45°

目的：让角点分布更均匀，提高数值稳定性。

## 四、常见错误（千万别做）

| ❌ 错误做法 | 后果 |
|:---:|:---|
| 所有照片都是正面、居中 | 焦距估计偏差大，畸变系数不准 |
| 棋盘格只占画面一点点 | 角点提取误差大，重投影误差飙升 |
| 手抖，画面模糊 | 亚像素角点检测失败，误差大 |
| 棋盘格反光 / 过曝 | 黑白格边界不清，角点检测失败 |
| 拍摄时棋盘格被遮挡 | 角点数量不对，整张图作废 |
| 连续拍很多张但几乎没动 | 信息冗余，对标定没有帮助 |

## 五、环境要求

1. **光照**：均匀漫反射，避免强光直射棋盘格（会反光）
2. **背景**：棋盘格背后不要太杂乱，但也不是必须纯色
3. **固定相机**：拍摄过程中相机**绝对不能动**，整个标定假设相机内参固定
4. **棋盘格平整**：打印的纸必须贴平（贴墙上或硬纸板上），不能皱褶

## 六、快速自检清单

拍完一组后，在 PC 上可以先粗略看看：

- [ ] 至少 15 张成功检测到角点
- [ ] 有棋盘格在画面边缘的照片
- [ ] 有棋盘格倾斜 >30° 的照片
- [ ] 有近景（占画面 >50%）和远景（占画面 <25%）
- [ ] 没有明显模糊的照片
- [ ] `calibrate_camera.py` 运行后重投影误差 < 1.0 px

如果误差 > 1.0 px，删掉误差最大的几张，补拍新的。

## 七、视频抽帧的应急方案

如果你确实想先录视频再抽帧，可以用下面这个脚本：

```bash
# 把视频按 0.5 秒间隔抽帧
ffmpeg -i your_video.mp4 -vf "fps=2" ./calib_images/frame_%03d.jpg
```

然后手动删掉：
- 模糊的帧
- 棋盘格没有完整出现在画面的帧
- 角度过于相似的帧（保留差异大的）

最终保留 15~30 张即可。
